## 1부. 현재 홈페이지 콘텐츠 구성 (As-Is)

| # | 섹션 (앵커) | 현재 역할 | 현재 핵심 카피 | 진단 |
|---|---|---|---|---|
| 0 | Nav | 이동 + CTA | 제품/신뢰/가속/요금제 · GitHub · 시작하기 | GitHub이 텍스트 링크뿐 — 스타 수 등 OSS 증거 없음 |
| 1 | Hero (#product) | 첫 인상 + 전환 | "AI의 실행을 조직의 성장으로" + 터미널 목업(uvx) + 대시보드 스크린샷 + 운영 원칙 인용 | ⚠️ 헤드라인이 추상적 — Factory 2.0의 조직 생산성 서사와 정면 충돌. 증빙이 일반 대시보드라 차별점(검증)을 안 보여줌. 터미널은 장식일 뿐 커맨드 복사 불가 |
| 2 | Trust (#trust) | Task→Trust 차별 | "맡기고, 확인하고, 신뢰합니다" + Claimed/Verified/Gate 씰 데모 | 💎 **유일한 무점유 니치(Claimed vs Verified)를 시연하는 섹션인데 3번째로 밀려 있고 비중이 작음** |
| 3 | Acceleration (#acceleration) | 학습 루프 | "더 빠르게 배우고, 더 크게 성장합니다" + 가설 피드 | 메시지가 제네릭 — 어떤 경쟁사도 반박 안 할 문장 = 차별 없음 |
| 4 | OrgOs | 조직 화면 소개 | "조직의 오늘과 다음을 한 화면에" + 카드 2 | 스크린샷 없는 텍스트 카드 — Proof와 역할 중복 |
| 5 | Customers (#customers) | 페르소나 | 창업자 겸 오퍼레이터 / AI 네이티브 제품 팀 / 스튜디오 | ⚠️ 타겟은 개발팀·프로덕트 팀인데 카드 3개 중 2개가 창업자/스튜디오 |
| 6 | Model (#model) | BYOA→관리형 경로 | "직접 운영하거나, 운영까지 맡기세요" | 구조 양호. 오픈코어 전환 서사의 핵심 |
| 7 | Proof (#proof) | 실 UI 증빙 | "화면으로 직접 확인하세요" + 스크린샷 3 | 실측상 경쟁사 다수가 실 UI 증빙 사용 — 방향 옳음. 단 검증 표면 스크린샷이 없음 |
| 8 | Pricing (#pricing) | 요금제 | $0 / $49 / $149 | ⚠️ 리서치가 찾은 웨지("컴플라이언스에 talk-to-sales 없음") 미활용 |
| 9 | FinalCta | 마지막 전환 | "AI의 속도를 조직의 성장으로 바꾸세요" | 히어로와 같은 추상 축 |
| 10 | Footer | 링크/상태 | 시스템 정상 pill | 양호 |

### 구조 진단 요약
1. **핵심 차별(검증)이 첫 화면에 없다** — 경쟁 전 랜딩에서 유일하게 비어 있는 "Claimed vs Verified" 니치를 우리가 이미 UI로 갖고 있으면서(#trust 씰), 히어로에서는 모두가 쓰는 추상 성장 서사를 말하고 있다. Multica(한국어, 동일 포지셔닝) 등장으로 선점 시급.
2. **OSS 신뢰 신호가 장식 수준** — 실측상 OSS 진영은 스타 수·복사 가능한 설치 커맨드 등 "실행 오브젝트"를 쓴다. 우리는 텍스트 링크와 장식 터미널뿐.
3. **중복·희석** — Acceleration/OrgOs/Customers가 제네릭 카피로 길이만 차지. 섹션 수 대비 논증 밀도가 낮다.

## 2부. 개선안 (To-Be)

### 메시지 위계 (단일 후킹 → 지지 논거)

```
후킹(Hero):     "AI가 했다는 것과, 검증된 것은 다릅니다."
왜 우리(Trust): 승인 Gate · 쉬운 Review · Advisor — Claimed를 Verified로 바꾸는 표면
어떻게(How):    스토리 등록 → 에이전트 실행 → Gate 승인 → Verified 기록 (한 루프)
누구(Who):      개발팀 · 프로덕트 팀 (혼성팀)
증거(Proof):    실 UI 스크린샷 + 오픈소스(스타·설치 커맨드)
전환(Model→Pricing): BYOA 무료 시작 → 관리형 $49 → 컴플라이언스 $149 (세일즈 게이트 없음)
```

### 히어로 헤드라인 후보 (선택 필요)

| 안 | 카피 (ko) | 근거 | 리스크 |
|---|---|---|---|
| **A (권장)** | **"AI가 했다는 것과, 검증된 것은 다릅니다."** 서브: "승인 Gate와 Review로, AI의 주장(Claimed)을 검증된 결과(Verified)로. 개발·프로덕트 팀을 위한 오픈소스 조직 OS." | 검증된 전 경쟁 랜딩 무점유 니치 직접 점유. 부정→해소 구조라 후킹 강함 | 부정문 시작이 부담이면 B |
| B | "AI 팀원은 많아졌습니다. 믿을 수 있는 결과는요?" 서브: "Sprintable은 승인 Gate와 Review로 Task를 Trust로 바꿉니다." | Vibe Kanban(선셋 중)의 병목 서사를 '속도'가 아닌 '신뢰'로 전유 | A보다 니치 직접성 낮음 |
| C (EN) | "Ship what's verified, not what's claimed." | 영문 로케일용 — A의 영어 대응 | — |

### 디자인 방향 (블루 시그니처 기준)

1. **다크 유지 + 블루 시그니처** — 현 oklch 다크 인디고 시스템 유지. 실측상 Linear Look 포화이므로 글로우 모방이 아니라 **"증거의 미학"**(씰·서명·게이트 UI가 곧 비주얼)으로 차별. 검증 ✓ 그린은 씰 내부 상태 색으로만.
2. **OSS 실행 오브젝트** — 스타 수 뱃지(히어로+네비), 복사 버튼 있는 설치 커맨드 칩. 장식 터미널은 씰 카드로 대체.
3. **타이포 유지** — Bricolage Grotesque. 세리프 추종 금지(Multica 선점).
4. **모노스페이스 부분 채용** — 커맨드 칩·씰 메타데이터(서명, 증거 수)에 한정.
5. **모션** — 기존 패럴렉스/리빌 시스템 유지. 히어로 씰 카드에 Claimed→Verified 상태 전환 애니메이션 1개 추가(제품 서사를 모션으로).
6. **금지** — 데이터 없는 지표 밴드(Factory 모방), 장식 아트 히어로(Paperclip 모방), "70% 다크" 같은 미검증 통계 기반 결정.

### 실행 순서 제안
1. 헤드라인 안 확정 (A/B 선택) ← **의사결정 필요**
2. Hero 개편 (씰 카드 승격 + 커맨드 칩 + 스타 뱃지) — 최대 임팩트
3. 섹션 재편 (Acceleration/OrgOs 통합, How it works 신설)
4. Pricing 웨지 카피 + Customers 재편
5. ko/en 메시지 파일 전면 정합화

### 미결 사항
- Team $49 과금 단위(per-seat vs flat) — 프라이싱 카피 확정에 필요
- GitHub 스타 수 노출 방식(실시간 API vs 정적) — 저장소 공개 스타 수 확인 필요
- Advisor 기능의 출시 상태 — "곧 제공" 라벨 여부
- 검증/게이트 화면 스크린샷 실물 확보 (현 screenshots/ 폴더에 해당 샷 없음)
