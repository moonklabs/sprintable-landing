## 제품 컨텍스트 (변경 금지)

- **제품**: Sprintable — 개발팀·프로덕트 팀을 위한 오픈소스 조직 OS. AI 에이전트를 정식 팀원처럼 등록해 사람과 같은 루프(스토리/스프린트/칸반)에서 실행시키고, 승인 Gate(HITL)·승인 전 쉬운 Review·Advisor(곧 제공)로 결과를 검증한다.
- **단일 후킹 메시지 (확정)**: ko "AI가 했다는 것과, 검증된 것은 다릅니다" / en "Ship what's verified, not what's claimed" — 경쟁 전수 조사에서 유일하게 무점유였던 "Claimed vs Verified" 니치를 점유하는 전략적 선택이다. 이 문장이 페이지의 왕이다.
- **시그니처 컬러 (확정)**: 브랜드 블루 `oklch(72% 0.14 258)`. 검증 그린 ✓은 UI 시맨틱(씰 상태)으로만 쓰고 브랜드 시그니처로 승격하지 않는다.
- **타이포 (확정)**: 디스플레이 Bricolage Grotesque, 본문 Barlow. 세리프 디스플레이 금지 — 직접 경쟁자 Multica(multica.ai)가 한국어 세리프 감성을 선점했으므로 기하 그로테스크 유지가 변별점이다.
- **프라이싱**: Free $0(셀프호스트 무제한) / Team $49 / Pro $149. 웨지 카피: "SSO · 감사 로그 · SLA — 영업 문의 없이 $149에 시작하세요."

## 콘텐츠 아키텍처 (확정 — 9 섹션, 카피는 messages/ko.json·en.json에 있음)

1. **Nav** — 제품/신뢰/요금제 · GitHub · 시작하기
2. **Hero** — 후킹 헤드라인 + Verified 씰 카드(주장→검증됨 스탬프 애니메이션) + 복사 가능한 `$ uvx sprintable` 커맨드 칩 + 대시보드 실 스크린샷
3. **Trust(Review 표면)** — "당신이 승인하기 전까지, 어떤 것도 Verified가 되지 않습니다" + 리뷰 3단계 + Advisor(곧 제공)
4. **How it works** — "모든 작업은 하나의 루프를 지납니다": 스토리 등록 → 에이전트 실행 → Gate 승인 → Verified 기록
5. **Proof** — 실 UI 스크린샷 3장 (public/screenshots/)
6. **Customers** — 개발팀 / 프로덕트 팀 / 창업자-오퍼레이터
7. **Model** — BYOA 무료 시작 ↔ 관리형 호스팅
8. **Pricing** — 3티어 + 컴플라이언스 웨지 콜아웃
9. **FinalCta** — "검증된 결과만 배포하세요" + 커맨드 칩

## 디자인 지시

### 1. 아름다움의 기준
- 최신 트렌드를 따르되 **모방이 아닌 종합**: "Linear Look"(다크+글로우+그리드)은 이 카테고리에서 포화 상태다. 다크 베이스는 유지하되, 글로우 장식이 아니라 **"증거의 미학"** — 씰, 서명, 게이트, diff 같은 검증 오브젝트 자체가 비주얼 아이덴티티가 되게 하라.
- 여백·타이포 스케일·리듬으로 고급감을 만들어라. 장식 요소를 추가할수록이 아니라 뺄수록 신뢰가 쌓인다.
- 라이트/다크 대비, 컬러 온도, 질감(노이즈·그레인·글래스)은 자유롭게 실험하되 시그니처 블루가 항상 위계의 정점에 있어야 한다.

### 2. 레퍼런스 (실측 검증된 사이트 — 방문해서 컨셉을 흡수하되 결과물은 우리 것이어야 한다)
- **paperclip.ing** — 콘텐츠 리듬의 기준: 한 섹션 = 하나의 단정적 주장(H2가 완결된 문장), 크림-온-웜블랙의 온도감, 설치 커맨드의 전면 배치, 풍부하되 과하지 않은 스크롤 애니메이션(149개 요소). 사용자가 가장 선호하는 레퍼런스.
- **linear.app/agents** — 절제의 기준: 순흑 배경에 장식 제로, 실제 제품 미니 창 3개가 유일한 증빙. "실 UI가 곧 메시지"의 정석.
- **factory.ai** — 산업적 정밀함(모노스페이스, 각진 버튼, 앰버 액센트)의 참고. 단, **데이터 없는 지표 밴드는 절대 모방 금지**.
- **conductor.build** — 리뷰/머지 UI를 히어로 증빙으로 쓰는 실례, 올-모노 타이포 아이덴티티.
- 이외 최신 트렌드 레퍼런스(예: vercel.com, resend.com, clerk.com 등)를 스스로 탐색해 흡수해도 좋다. 단 반드시 실제 방문·확인 후 적용하라.

### 3. 모션 (적당히 멋지게 — 과하면 신뢰가 깎인다)
- 기존 모션 시스템을 활용·확장하라: `app/components/motion/scroll-reveal.tsx`(IO+스크롤 폴백), `parallax.tsx`(rAF), globals.css의 오로라 오브·도트 그리드·카드 리프트·CTA 글로우·shimmer·씰 스탬프 keyframes.
- 필수 유지: 히어로 씰 카드의 **주장→검증됨 스탬프 사이클**(8s) — 제품 약속이 모션 그 자체인 장치다. 더 아름답게 다듬는 것은 환영.
- 스태거 등장, 패럴렉스 심도, 호버 마이크로 인터랙션은 유지·개선. `prefers-reduced-motion` 폴백 필수(기존 시스템에 구현돼 있음).
- 60fps를 깨는 효과(대형 blur 남발, 레이아웃 스래싱) 금지. transform/opacity 기반으로.

### 4. 신뢰감 (B2B — 최우선 가치)
- 이 페이지의 구매자는 개발팀·프로덕트 팀 리더다. 화려함이 신뢰를 이기면 실패다.
- OSS 신뢰 신호는 "실행 오브젝트"로: 복사 가능한 설치 커맨드, GitHub 버튼(가짜 스타 수 표기 금지 — 실 데이터 없으면 수치 생략), 실 UI 스크린샷.
- **금지**: 가짜 지표·고객 로고·통계, 스톡 일러스트, 존재하지 않는 기능의 UI 목업. Advisor는 반드시 "곧 제공" 라벨 유지.
- 접근성: 대비 WCAG AA, 키보드 포커스 스타일, aria 유지.

### 5. 기술 제약
- Next.js **16.2.4** — 이 버전은 학습 데이터와 다를 수 있다. 코드 작성 전 `node_modules/next/dist/docs/`의 관련 가이드를 반드시 읽어라 (AGENTS.md 지시).
- Tailwind CSS v4(`@theme inline`), OKLCH 컬러 시스템(globals.css), next-intl(ko/en — **모든 카피 변경은 messages/ko.json과 en.json 동시 반영**), edge runtime, CF Pages 배포(`images.unoptimized`).
- 카피 수정은 뉘앙스 다듬기 수준만 허용. 메시지 축·섹션 구조 변경은 금지.
- 작업 브랜치: `feat/landing-claimed-vs-verified` 위에서 진행 (main 직접 작업 금지).
