- 분석일: 2026-07-30

- 분석 환경: 데스크톱 1920×911, 모바일 390×844
- 분석 범위: 정보 구조, 메시지 위계, CTA, 제품 증거, 신뢰 장치, 비주얼 시스템, 반응형 변화, 상호작용

## 1. 핵심 요약

Orca 랜딩페이지는 기능 목록으로 시작하지 않는다. 먼저 새로운 제품 범주인 `ADE(Agent Development Environment)`를 선언하고, 개발자가 즉시 이해할 수 있는 실제 제품 화면으로 주장을 증명한다.

전체 설득 흐름은 다음과 같다.

> 강한 결과 약속 → 실제 제품 데모 → 개발 워크플로우 → 호환성 → 기능 증거 → 사용자 증언 → 경쟁 비교 → FAQ → 다운로드

Orca가 개발자에게 효과적인 이유는 세 가지다.

1. 모든 주장을 브랜치, 워크트리, 터미널, diff, 테스트, PR 같은 개발자 네이티브 오브젝트로 보여준다.
2. 다운로드, GitHub, 지원 OS를 첫 화면에서 바로 제공해 도입 마찰을 줄인다.
3. 제품 증거, 오픈소스 신호, 사용자 증언, 비교표, FAQ를 순차적으로 쌓아 구매·도입 불안을 해소한다.

## 2. 타깃과 포지셔닝

### 핵심 타깃

- 여러 AI 코딩 에이전트를 동시에 사용하는 개발자
- Claude Code, Codex, OpenCode 등 기존 CLI 에이전트 사용을 유지하고 싶은 개발자
- 워크트리, 터미널, 브라우저, PR 리뷰를 하나의 개발 환경에서 처리하려는 개발자
- 원격 또는 모바일에서도 에이전트 실행 상태를 관리하려는 개발자
- 기존 IDE나 단순 터미널 래퍼의 한계를 느끼는 고관여 사용자

### 포지셔닝 방식

Orca는 자신을 일반 IDE나 에이전트 터미널 래퍼가 아니라 `ADE`로 정의한다.

제품 범주를 새로 정의함으로써 다음 비교 구도를 만든다.

| 기존 범주 | 한계로 제시하는 내용 | Orca가 제안하는 대안 |
| --- | --- | --- |
| 전통적인 IDE | 사람 중심으로 설계됨 | 사람과 에이전트를 함께 관리하는 환경 |
| 병렬 에이전트 래퍼 | 터미널 수준에서 멈춤 | 파일, 브라우저, diff, git, PR까지 포함 |
| 단일 에이전트 도구 | 동시 실행과 격리가 제한적 | 워크트리 단위의 병렬 실행 |

### Hero 메시지

Hero의 핵심 문장은 **“Ship 100x With The Agent IDE”**다.

이 문장은 다음 세 가지를 한 번에 전달한다.

1. 결과: 더 빠른 배포
2. 메커니즘: AI 에이전트를 위한 IDE
3. 범주: 기존 IDE와 다른 Agent IDE

`100x`는 강한 후킹 장치이지만 랜딩 내부에 정량적 근거는 제시되지 않는다. 이후의 제품 데모와 사용자 증언이 이 과장 가능성을 보완하는 구조다.

## 4. Header 분석

### 콘텐츠

- Orca 로고
- Docs
- Changelog
- Enterprise
- Discord
- X
- GitHub 스타 수
- Download

### 비주얼

- 높이: 약 56px
- 위치: 화면 상단 고정
- 배경: 약 85% 불투명 검정
- 효과: 약 24px 배경 블러
- 하단: 흰색 8% 수준의 얇은 경계선
- Primary CTA: 흰 배경과 검은 텍스트

### 역할

Header는 탐색 메뉴보다 신뢰와 전환을 우선한다. GitHub 스타와 Download가 항상 노출되므로 방문자는 어느 스크롤 위치에서도 제품 신뢰도와 다음 행동을 확인할 수 있다.

### 모바일 변화

- Docs, Changelog, Enterprise, 소셜 아이콘 숨김
- 로고 유지
- GitHub 스타를 큰 pill로 노출
- 햄버거 메뉴 제공

모바일에서도 GitHub 스타는 숨기지 않는다. 이는 오픈소스 신뢰가 제품 탐색보다 우선순위가 높다는 뜻이다.

## 6. 제품 데모 및 개발 루프

### Hero 데모 탭

Hero 데모는 다음 사용 시나리오를 탭으로 분리한다.

- 여러 에이전트 동시 실행
- 반복 업무 자동화
- AI 결과 리뷰
- Git 연동
- 이동 중 작업 관리

탭은 하나의 복잡한 제품 화면을 여러 가치 제안으로 재사용하는 장치다. 제품 전체 화면을 반복해서 보여주지 않고 사용 목적에 따라 초점을 변경한다.

### 개발 루프 섹션

**“Your dev loop, agentified.”**라는 섹션은 다음 개발 활동을 하나의 제품 범위로 묶는다.

- 워크스페이스
- 오케스트레이션
- 브라우저
- 터미널
- 태스크
- 에디터
- 노트
- AI 기반 배포

### 레이아웃

- H2 중앙 정렬
- H2 아래 가로 탭
- 본문은 좌측 설명, 우측 제품 데모의 비대칭 2열
- 선택된 탭은 흰색 pill, 나머지는 회색 텍스트
- 제품 화면 내부의 선택 영역은 파란 테두리와 발광 포인트로 강조

### 설득 효과

기능을 카드로 나열하기 전에 “기존 개발 루프 전체가 제품 안에 있다”는 큰 그림을 전달한다. 이후의 기능 카드는 이 주장에 대한 세부 증거 역할을 한다.

## 7. 호환성 및 락인 해소

**“Bring your own Agent / Subscription”** 섹션은 기존 CLI 에이전트와 구독을 계속 사용할 수 있다는 점을 강조한다.

### 콘텐츠 역할

- 새로운 모델 계약이 필요하지 않음
- 기존 CLI 에이전트를 교체할 필요가 없음
- 여러 에이전트를 한 제품에서 병렬 실행 가능
- 특정 모델 공급자에 종속되지 않음

### 비주얼

- 중앙 정렬된 H2와 짧은 설명
- 지원 도구를 작은 pill 형태로 다수 노출
- 브랜드 아이콘과 이름을 함께 사용
- 마지막에 범용 CLI 지원을 암시하는 확장 항목 배치

### 분석

개발자 제품에서 호환성은 기능이 아니라 위험 제거 장치다. Orca는 기능 설명 중간에 이 섹션을 배치해 방문자가 “기존 도구를 버려야 하는가?”라고 생각하기 전에 답한다.

## 8. Agent-first 및 모바일 동반 앱

**“Agent-first, end to end.”**는 IDE와 ADE의 차이를 다시 선언한다.

### 메시지

전통적인 IDE가 사람을 위해 만들어졌다면 ADE는 사람과 에이전트가 함께 일하는 데 필요한 워크트리, 터미널, 브라우저, CLI를 한 환경에 제공한다는 논리다.

### 모바일 카드

- 큰 2열 카드
- 좌측: 설명과 플랫폼별 CTA
- 우측: 실제 모바일 UI
- 약 60:40 비율
- 카드 배경: #0A0A0A에 가까운 차콜
- 얇은 흰색 10% 경계선
- 약 16px radius

### 모바일 가치 제안

- 실시간 에이전트 상태 확인
- 사용량 확인
- 계정 전환
- 원격 터미널 작업 지속
- 데스크톱 연결 상태 확인

제품의 핵심 가치를 “더 많은 기능”이 아니라 “책상 밖에서도 에이전트를 멈추지 않는다”는 연속성으로 확장한다.

## 10. 사회적 증거

### 초기 증거

- Hero 상단의 YC 배킹
- Header의 GitHub 스타 수
- 기술 기업 소속 빌더 로고 스트립

### 후기 섹션

**“Builders who ship with Orca.”** 아래에 실제 X 게시물 형태의 카드를 배치한다.

각 카드에는 다음 요소가 포함된다.

- 사용자 이름과 프로필 이미지
- 계정 핸들
- 게시 날짜
- 원문 형태의 후기
- 좋아요와 답글 수
- 스크린샷 또는 영상
- 실제 게시물 링크

### 비주얼

- 3열 masonry 형태
- 카드 높이가 서로 달라 피드 같은 인상
- X의 인터페이스 문법을 유지
- 제품 이미지가 포함된 게시물이 시각적 리듬을 만듦

### 장점

- 편집된 짧은 인용문보다 실제성이 높음
- 작성자와 날짜를 확인할 수 있음
- 제품이 현재 사용되고 있다는 느낌을 줌

### 단점

- 섹션 길이가 매우 길어짐
- 게시물마다 정보 밀도가 높아 핵심 후기를 빠르게 훑기 어려움
- 반복되는 카드 UI로 시각적 피로가 발생

### 주의

## 16. 모션과 상호작용

### 진입 모션

Hero 요소는 약 0.8초의 fade-up을 사용한다.

관찰된 지연 순서:

- 배킹 배지: 약 50ms
- H1: 약 100ms
- 본문: 약 250ms
- CTA: 약 300ms

모든 요소를 동시에 등장시키지 않고 메시지 순서대로 노출한다.

### 탭 인터랙션

- 선택 탭은 흰색 pill 또는 높은 명도의 텍스트
- 비선택 탭은 낮은 명도의 회색
- 약 200ms 색상 전환
- 모바일에서는 가로 스크롤 레일

### 기능 카드

- 카드 Hover 시 경계선 강조
- 이미지 위에 어두운 그라데이션과 inspect 힌트
- 클릭 시 상세 모달

### 제품 데모 모션의 역할

모션은 배경 장식이 아니라 다음 제품 상태를 설명한다.

- 에이전트 활성 상태
- 현재 선택된 작업
- 브라우저에서 선택한 UI 요소
- 작업 진행과 완료 상태
- 모바일 원격 연결

## 18. 강점과 약점

### 강점

1. 제품의 실제 UI가 랜딩의 주된 시각 자산이다.
2. 메시지와 CTA의 우선순위가 명확하다.
3. 개발자가 사용하는 용어와 오브젝트를 그대로 사용한다.
4. 기존 에이전트와 구독을 유지할 수 있어 도입 불안을 줄인다.
5. 오픈소스, GitHub, 사용자 게시물, 비교표, FAQ가 단계적으로 신뢰를 쌓는다.
6. Desktop과 Mobile의 CTA 목적을 다르게 설계한다.
7. 기능 카드가 상세 제품 탐색 인터페이스로 동작한다.

### 약점

1. `100x` 주장에 직접적인 정량 근거가 없다.
2. 전체 페이지가 검정과 회색 중심이라 후반부 시각 변화가 적다.
3. 일부 본문과 비교표의 회색 텍스트 대비가 낮다.
4. 사용자 후기 섹션이 길고 반복적이다.
5. 큰 수직 여백으로 전체 페이지가 매우 길다.
6. 모바일에서 CTA가 제품 데모보다 과도하게 앞선다.
7. 회사 로고가 공식 고객사로 오해될 가능성이 있다.

## 19. Sprintable에 적용할 수 있는 패턴

### 적용 가치가 높은 패턴

1. Hero에서 추상 이미지 대신 실제 Gate/Review 화면 사용
2. 실제 diff, 테스트, 로그, 승인 상태를 개발자 네이티브 오브젝트로 표현
3. 지원 에이전트와 MCP 호환성을 별도 섹션으로 명시
4. GitHub, Docs, Changelog를 Header에서 노출
5. 실제 기능 화면을 클릭해 상세 탐색할 수 있는 갤러리
6. Sprintable과 일반 PM·에이전트 관리 도구의 비교표
7. 보안, 셀프호스트, 데이터, 호환성, 승인 병목 FAQ
8. 현재 기기와 제품 상태에 맞는 CTA 분기

### 그대로 복제하지 않을 패턴

1. 근거 없는 배수 생산성 주장
2. 확인되지 않은 회사 로고
3. 너무 긴 사용자 후기 masonry
4. 전체 페이지를 검정 단색으로 구성하는 방식
5. 제품 증거보다 많은 기능 카드
6. 모바일 첫 화면의 과도한 CTA 스택

## 20. 증거와 해석의 경계

### 직접 확인한 내용

- 현재 섹션 순서와 카피 구조
- Desktop과 Mobile CTA 차이
- GitHub 스타 표시
- 기능 카드 13개
- 비교표의 10개 기준
- FAQ의 질문 범주
- 사용 서체, 크기, 컨테이너 폭, 배경색, 경계선, 모션 시간
- 기능 카드 클릭 시 상세 모달 동작

### 해석

- ADE 범주 정의는 기존 IDE와 직접 비교하지 않고 새로운 선택 기준을 만들기 위한 전략이다.
- 호환성 섹션은 기능 설명보다 락인 우려 제거 역할이 크다.
- 실제 X 게시물은 정제된 testimonial보다 신뢰감을 높이지만 가독성과 페이지 길이를 희생한다.
- 모바일 CTA 전환은 단순 반응형이 아니라 기기별 획득 전략이다.

### 확인할 수 없는 내용

- 회사 로고와 공식 고객 관계
- 비교표에 포함된 타 제품 판정의 객관성
- 생산성 배수 주장에 대한 정량 검증
- 모든 제품 데모 데이터가 실제 사용자 데이터인지 여부
